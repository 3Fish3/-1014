# RM 电控三维教学系统 UI V2 重设计任务书

## 1. 改版目标

把现有 `hushi_ec_teach` V1 从“暗色工程控制台”改为“90 分钟电控入门讲座的投影展示系统”。本次优先解决**视觉层次、三维模型比例、教学投影可读性和演示节奏**。不做底层渲染架构重写，不更改已经验收的差速运动学逻辑。不得牺牲现有功能。

目标受众：多数不了解机器人、部分学过 C 语言或基础电路的新学员。教学侧重点是认识硬件、功能和基本工作流程。界面应由讲师操作，讲师口头解释详细原理。

## 2. V1 视觉诊断（基于实际交付截图）

1. 暗色背景、细青色描边、微小控件过于密集，整体像监控/调试系统。
2. 三维模型在画布内占比偏小，尤其第 10 步英雄机器人对照，存在明显镜头与装配偏置问题。
3. 左栏混用标题、讲师参考词、图解、实物照片、细节列表、源码入口，信息主次不清。
4. 顶部导航、画布下方工具栏、底部按钮区叠加，视觉噪声大。
5. 实物照片过小，重复使用整车图片，无法承担“认识器件”的教学目标。
6. 1080p 教室投影下字号和对比度不足。

## 3. 视觉方案（首选）

采用**蓝白科技教学/产品展厅风格**，而不是游戏 HUD、深色仪表盘或高密度管理后台。

建议设计令牌（可微调）：
- 主背景 `#F5F7FB`，内容卡片 `#FFFFFF`
- 主文字 `#14213D`，次级文字 `#526175`
- 强调 `#2563EB`，浅强调 `#EAF2FF`
- 分隔线 `#E4EAF2`，阴影轻柔、卡片圆角 16–20px
- 控制路径颜色固定语义：供电橙、通信蓝、反馈绿；始终附图例
- 中文字体使用系统稳定字体栈，避免依赖外网

不要大量使用荧光描边、玻璃拟态、全大写标签、花哨赛博朋克元素或无意义图标。

## 4. 1920×1080 投影布局

- **顶栏（约 72–88px）**：章节标题 + 当前教学步数（如 03/10）+ 可见的全屏开关。隐藏多余工具。
- **主体左侧（宽度约 68%–72%）**：清爽的 3D 演示台。模型清晰、自动适应镜头、始终在主体视觉中心；不放厚重边框。保留视角切换但放到低关注度位置。
- **主体右侧（宽度约 28%–32%）**：当前部件标题（30–36px）、一句核心问题、实物大照片、2–3 句功能说明、最多 3 个知识关键词。图片大且清楚，不用长段落。
- **底栏（约 72–88px）**：上一页 / 当前小节 / 下一步。仅在动作演示步骤出现预设动作按钮和无数值左右轮滑块；可使用展开的浮动操作板，不遮挡模型。
- **讲师参考**：默认不显示在学员投影画面中。如必须保留，进入讲师备注视图或侧抽屉，且不能影响主画面。

建议展示文字最低标准（1080p）：章节标题约 30–40px，正文约 22–26px，关键词 20–24px。较小辅助信息也应可读，且不得占据主体。

## 5. 页面类型及交互

### A. 常规组装步骤（1–7）
- 左侧显示对应阶段的小车模型，新装部件用简短高亮/淡入/装配运动提示。
- 相机平滑对准新增部件；避免穿模、裁切或离画面太远。
- 右侧突出**一个**部件，真实照片优先、示意图片标注用途，不复用无关整车照片。
- 文案结构：疑问句 → 名称 → 两句通俗用途说明 → 关键词。
- 教学动画**讲师手动分步**，不能自动抢节奏。

### B. 底盘运动步骤（8–9）
- 预设动作：前进、后退、左转、右转。
- 单独控制左轮与右轮：两个无数值滑块，能调正反向和快慢。
- 轮子显示旋转箭头，小车显示运动轨迹；图例清晰。
- 固定视角/跟随视角切换。
- 控制与动力的传递过程采用**逐步播放的动态连接线**；不要同时闪烁所有线路。
- 禁止在学生版显示 RPM、PWM 及代码片段。

### C. 英雄机器人对照（10）
- 采用真正的左右双视区或清晰的对照展示，保证两个模型均有足够大的主体占比。
- 各自独立计算几何边界与 camera fit，核对方向、缩放、离散子装配体及偏置。
- 不要为了容纳远离主体的异常几何而把整车缩成一个点；异常件应核查归属并正确标注，不能悄悄删除真实结构。
- 对应部件明确标示：车架、车轮、驱动、主控、供电（以实际核实结果为准）。
- 尚未确认英雄机器人底盘类型时，不得标注为麦克纳姆轮或舵轮。

## 6. 必须保留的 V1 能力

1. 10 步教学结构及上一页/下一步。
2. 本地离线加载 Three.js、GLB、照片。
3. 双轮差速运动学与 6 个现有单元测试。
4. 左右轮独立调节，不显示数值。
5. 预设动作、轨迹、方向箭头、相机视角切换。
6. 控制/供电/反馈关系的分步骤解释。
7. 英雄机器人模型对照及来源/示意标识。

保留原教学内容和 `agent.md` 教学人格，不要以 UI 改版为由改写教学目标。

## 7. 交付验收

- 在 1920×1080 和 1366×768 截图或录像验收，重点看模型大小、文字可读性、按钮可见性和界面溢出。
- 至少提供第 1、3、7、9、10 步的**真实浏览器截图**。不能用概念图冒充。
- 提供交互演示录像，实测上一页/下一步、动画暂停/切换、独立左右轮滑块、轨迹与视角切换。
- 第 10 步两个模型主体占比应明显优于 V1，且不出现裁切、镜头偏置。
- 在实际课堂设备或等效设备上记录加载时间、帧率和异常行为。
- 现有测试全通过，新增基本页面/交互验收；问题如实记录。

## 8. 实施顺序

P0：先只重设计第 3 步静态教学页和第 9 步运动交互页，输出真实截图审查。先定视觉，后批量套用全部 10 步。

P1：完成全部步骤排版、照片与投影可读性，修正第 10 步镜头和模型对照。

P2：润色装配动画、细节过渡与教师备注入口，进行最终 1080p 投影验收。

**禁止直接进入第三章开发。当前目标是将第二章 V1 打磨成能在教室直接使用的高质量教学界面。**
