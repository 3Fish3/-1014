## 克隆后如何运行

在项目根目录运行：

```bash
python3 scripts/run_motor_lab_local.py --port 8081
```

打开 `http://127.0.0.1:8081/`。脚本只绑定本机回环地址，采用标准库，无需先安装Python依赖。

该分支的六个运行模型已存入`assets/motor-lab/`，服务映射不再依赖原开发机`.tmp`。不要用简单`web/`静态服务器代替：网页仍通过`/motor-lab-models/<id>.glb`白名单取模型。这里不是GitHub Pages部署，也没有启动公网服务。

代码阅读/3D文件检查无需运行Node测试；浏览器回归的Playwright/Chromium依赖按项目现有环境自行准备，本次未安装或重跑。

## 现有行为

- 六个源模型：TB47D、兼容电池架、电调中心板2、C板、C620、M3508；电池架按安装图在颈部展示，中心板/电调正面已翻正。
- 供电三链路、CAN两链路、三相和7-pin数据共七链路；自动接线和鼠标拖线操作同一个SIM连接状态。
- 端点从命名插座/CAD区域求世界坐标与法线；曲线先沿法线离面，再绕过器件。穿入诊断是包围盒粗筛＋可见三角面的有限射线抽查，不是精确连续碰撞认证。
- 允许旋转、平移、缩放、聚焦、复位及面板折叠。缺少任一源模型时禁用操作并提示，不退回方块假装加载成功。
- 固定24V是教学SIM约定；转速/故障/报文为软件计算，不连接硬件，不把整个电机机身转动当真实轴动画。

## 请网页审核重点检查

1. **布局**：中心板拟绕世界竖直轴旋转180°，保持正面朝上，重新计算端口世界法线，使XT60面向电池、XT30合理面向C板/C620。该建议尚未落实现。
2. **走线**：当前为避障抬高的拱线仍偏大；应先优化器件朝向、端口相向和出线路径，再缩短高拱，不能靠穿过模型来缩短。
3. **接口真实性**：彩色端点、线头仍是功能级示意；C板CAN1与CAN2不能混为同一引脚；电池架输出身份/精确线端型号、针序与配合面待核。
4. **图形与交互**：源模型大小、统一尺度、端点选取、Orbit与拖线冲突、面板折叠后尺寸、线身/材质资源释放。
5. **可复现**：由稳定资产映射启动六模型，不依赖开发机绝对路径；归档历史脚本保留旧任务路径，仅作制作依据，不是当前生产构建脚本。
6. **拒收项**：4310无GLB、开关外形不合格、XT60仅板端，不得据目录存在就判定为已完成线束。
