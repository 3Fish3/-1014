# 模型与直接接线复核

## 用户反馈与复现

用户反馈：需要重新检查建模，器件看起来不能直接接线。本轮只做实际问题诊断与交互修复，不把功能原型升级称为高保真模型。

主模型复现：`node .tmp/motor-lab-drag-repro.mjs`，从电源端拖到中心板端松手，`connections: []`，断言失败。即使先点击全局机位再拖动，仍然失败，说明不单是镜头问题。复现脚本临时保留，本轮长期回归纳入 `tests/motor_lab.browser.mjs`。

## 审查发现

1. 原 `setupInteractionEvents()` 只处理pointerdown的两次点选，没有拖动到端口松手的连接路径；用户自然拖线时只选起点，不会连接。
2. 端口使用原始小方块的几何射线命中，窄画布全局视角下点选范围小，缺少屏幕空间容错。
3. `fitCameraToScene()`此前只在重置机位/窗口resize时应用；主模型新页1366×768截图 `recheck-initial.png` 显示首次加载电源和电机裁出画布。此前验收截图在reset/resize后，遗漏了这个首次加载场景，不能继续声称全部视角已验证。
4. 器件均为程序化功能占位，不是此前调查模型的实际导入。M3508外壳长径比、法兰/安装孔、接头形态没有按已核手册/实物图重建；不能用贴了型号标签替代外形验收。
5. 部分端口位置与外壳不贴合：电机后端面约x=2.37，端口中心原x=2.15，形成可见间隙。主控无外壳、板件示意构件不具备逐件原图对应证据，接口方块没有真实键位与端面结构。
6. 线材是单条功能曲线，未表达实际两芯/三相/7芯端面；只能讲链路，不是可照抄的实物装配与逐针教程。

## 本轮修复目标与排除项

- 保留两次点击与面板自动接线，新增端口起手→匹配端口松手拖线；共用逻辑connect与错误配对规则。
- 屏幕空间命中容错、端口高亮/名字提示、拖动中反馈，正常空白区仍能旋转；结束/取消恢复镜头控制。
- 首次加载应用全局机位，不依赖用户手动重置。
- 模型真实性审查单独不通过：本轮交互修复不能当作M3508/C620/C板/中心板精确模型完成。替换真实资源或按图重建需另逐件验收，保留未核实端口标记。
