# Motor Lab 独立网页：计划、进度与验收

## 当前范围与结果

版本：独立教学原型 v0.1，基于 main@13f45c4 的新增文件，尚未提交/推送。用户授权主代理指导、子代理实现、主代理短轮审查修正，睡眠期间继续推进。

**独立网页阶段功能验收通过**：单页完成五类虚拟器件认知、7条功能级连线、启停调速、受限代码输入、故障诊断与恢复。不是最终高保真资源验收，也未接入实际硬件。

入口：`web/motor-lab.html`。需以 `web/` 为HTTP服务根目录，ES模块不支持直接以file://双击运行。已有静态服务可用时访问 `http://127.0.0.1:8080/motor-lab.html`，服务状态须现场核验。

## 实现计划与实际路径

1. 查官方手册、图片与可用三维资源：形成研究根目录 `.tmp/motor-lab-asset-research/交付/` 的10项交付与来源JSON；一些候选仍未完成许可/精确版本复核。
2. 建立独立原型：表现层与纯状态逻辑分离，无新依赖，无外部CDN/字体/图片请求。器件采用本项目程序化近似外形，不下载未知许可网格到课件。
3. 主代理实测并审查：修复ID合法性、相机裁切、重置输入同步、模拟暂停/单步、手机工具栏裁切、RPM与真实CAN电流混用等问题。
4. 独立原型验收后再并入主课件：**本轮未修改第一/二章入口或状态流**，当前仅提供返回第一章/前往第二章链接。下一阶段最小集成可先加课程入口，不自动引入学习进度系统。

计划变化：原先偏重STEP与补拍的调查方式已按用户纠正调整为不限三维格式、优先网上/官方PDF现成图片。为避免版权与精确模型等待阻塞功能闭环，先实现标注近似的原型；不把近似原型说成全部P0实物模型已齐。

## 文件与接口

| 文件 | 职责 |
|---|---|
| `web/motor-lab.html` | 独立入口、器件与接线列表、运行/故障/代码/教学引导面板 |
| `web/css/motor-lab.css` | 桌面三栏、面板折叠、投影色彩与手机纵向布局 |

| `web/js/motor-lab/sim.js` | 可序列状态、连线校验、阻塞诊断、确定性步进、CAN命令编码与受限脚本解析 |

| `tests/motor_lab.browser.mjs` | 独立运行的27项离线浏览器验收及截图，未接入现有CI |

## 已完成行为

- 五类程序化器件：虚拟24V电源、候选中心板2、C型主控、C620、M3508。电源未选实物型号；所有端口为功能示意、未知逐针UNVERIFIED。
- 7条链路：电源→中心板；中心板→主控；中心板→电调；主控→CAN并联网络；该网络→电调；电调→电机三相；电调→电机7-pin。
- 依次点击3D两端接线、拒绝错误配对、列表连接/断开、自动接线；自动/手动更新同一状态。当前不是自由拖拽插拔或真实针脚仿真。
- 启停、电源、±3000转子RPM目标、合法1–8 ID匹配、CAN/电源/专用数据/三相故障；阻塞时转速按教学模型渐减，恢复后可重新响应。
- 一阶SIM响应不是参数标定的M3508动力学或PID固件；输出轴转速用转子RPM除以3591/187，轴绕本地轴心显示。内部旋转标记是教学可视化，不是内部机械结构认证。
- 模拟时间暂停/继续与电机运行状态独立；单步仅推进0.05秒并暂停自动时间。重置同步全部数值/ID/故障控件。
- 代码只接受 `set_target_rpm(1, integer); start_motor(1); stop_motor(1);`，不执行JavaScript/C++，不调用真实硬件。非法/过长/超范围输入失败且不污染状态。
- 转速来自SIM；电流/温度明确未建模、无硬件采样。真实CAN区只给固定离线编码算例，不由RPM直接制造电流raw，不随动画伪造温度。反馈字节是人工构造的参考帧，不是官方抓包。
- 相机全局/电机/电调/主控预设、缩放旋转、面板折叠与投影色彩，保持接线状态；手机导航/工具可访问、正文竖向滚动。

## 主代理验证记录

实际复跑，而非仅采纳子代理自述：

- `npm test`：81项通过（原67项＋本轮14项），0失败。
- `node tests/motor_lab.browser.mjs`：27项通过，0页面错误、0非本地请求。包含真正canvas点击两端接线/错误配对、自动与列表接线、运行/反转、故障恢复、ID阻塞、数据断线、拔电调供电后示例离线、脚本注入拒绝、重置控件、暂停/单步/继续、手机完整运行。
- 布局及截图：1920×1080、1366×768、390×844；主模型查看桌面与手机截图。首轮裁切/手机导航隐藏已修。画布未裁五类器件，手机页面可纵向完整访问。
- 浏览器环境：本地已有Chromium＋SwiftShader；未安装新浏览器。默认Playwright缓存浏览器不可用时使用 `.tmp/browser/chrome-linux/chrome`，可用 `BROWSER_PATH` 覆盖。
- 最后LSP错误探测为4文件中3确认clean、1文件静默回报无法确认；不能把空诊断当作四文件全部clean。另执行Node语法检查及实际模块浏览器加载。未运行Firefox、真实GPU、教室投影实测。
- 产物：`.tmp/motor-lab-browser/report.json`及各分辨率截图；临时早期脚本保留作过程证据，长期复跑以tests中的脚本为准。

浏览器命令支持 `BASE_URL`、`BROWSER_PATH`、`MOTOR_LAB_OUTPUT`；先启动现有静态服务器，再运行测试。截图与报告由测试写入.tmp，不提交构建缓存。

## 用户实用性复核后的增量修正

上一轮27项是功能原型的历史验证，不覆盖首次打开/拖线。用户反馈后补充测试确认：首次加载相机未fit、拖线无松手处理、小端口难命中。主模型已直接修复，详见[模型与接线复核](模型与接线复核.md)。

当前浏览器回归为31项通过（新增首次加载拖线、错误拖线、8px容错、取消后恢复）；单元测试仍81项通过。支持端口起手拖动、目标松手接线，保留两次点击；悬停高亮/12px屏幕容错/虚线预览，空白拖动继续控制镜头。首次加载全局取景已补，两个电机示意端口贴近外壳。所有变化为局部交互与示意贴合，不是精确建模完成。

## 尚未完成及下一阶段

1. 官方/社区精确模型及现成图片的许可、版本与端口几何仍未齐；可用近似模型满足功能原型，不满足全部P0高保真资产配套。
2. 已支持从端口拖到端口的功能级接线，但尚未实现自由摆放线缆、精确键位/针脚配对；是否需要线缆物理碰撞由实际教学需要决定，**不把复杂物理引擎新增为既定验收要求**。
3. 尚未并入主课件入口。用户路线是先独立验收后集成；后续在不改变既有课件运行的前提下做最小入口改动。
4. 未做目标投影设备试讲与真实性能/内存测量；GLB文件体积不是进程内存，软件渲染不是物理投影验收。
5. 没有硬件通电、固件刷写、真实CAN/UART访问；页面的指示灯/故障为教学规则，不当作真实C620灯码或设备失效机理。
