# Motor Lab 真实模型本地运行说明

> 适用范围：本地开发与验收专用。**本服务与说明仅用于本地预览，不构成任何公开分发授权**；
> 白名单内的 GLB 源文件不会被复制进 web/、不会被纳入默认 zip 包，也不代表其许可允许再分发。

## 一、启动服务

```bash
python3 scripts/run_motor_lab_local.py            # 默认 port 0，由系统分配
python3 scripts/run_motor_lab_local.py --port 8765  # 指定端口
```

- 仅绑定 `127.0.0.1`，不对外网暴露。
- 启动后第一行输出就绪 JSON，包含实际 `url` 与白名单 `models` 映射，例如：

```json
{"event":"motor-lab-local-server","url":"http://127.0.0.1:41163/","port":41163,"models":{...}}
```

- 该服务独立于 `scripts/run_server.sh`（8080），可并存运行；退出用 Ctrl+C。

## 二、安全边界

- `web/` 作为普通静态目录；**禁止目录列表**（目录请求一律 404）、**禁止路径穿越**
  （含 `..`、`%2e%2e`、双重编码变体，统一 404）、**禁止符号链接跳出** web 根
  （所有路径 resolve 后校验仍位于 `web/` 内）。
- 真实模型走显式白名单路由 `/motor-lab-models/{id}.glb`，仅限下表来源：

| id | 磁盘来源（相对项目根） |
| --- | --- |
| `c-board` | `assets/motor-lab/c-board/c-board-official-white-silver.glb` |
| `center-board2` | `.tmp/motor-lab-models/center-board2/output/web.glb` |
| `c620` | `.tmp/motor-lab-models/c620/output/web.glb` |
| `m3508` | `.tmp/motor-lab-models/m3508-audit/output/review.glb` |
| `tb47d` | `.tmp/motor-lab-power-chain/assembly-step/output/battery.glb`（缺失时回退 `.tmp/motor-lab-power-chain/tb47d-local/output/web.glb`） |
| `battery-rack` | `.tmp/motor-lab-power-chain/battery-rack/output/web.glb` |

- 白名单外 id 返回 404；`.tmp/`、`assets/` 本身不作为目录暴露。
- 所有响应带 `Content-Type`、`Content-Length` 与 `Cache-Control: no-store`。
- 不回显任何绝对敏感路径；错误响应仅为 JSON `{"error":...}`。

> 关于 `tb47d`：当前实现按优先级取 `assembly-step/output/battery.glb`，不存在时回退
> `tb47d-local/output/web.glb`，与需求一致（回退逻辑在服务端按文件存在性判断）。

## 三、端到端验收测试

```bash
node tests/motor_lab.real.browser.mjs
```

- 测试自行 `spawn` 一次上述服务（port 0），解析 readiness JSON 拿 URL，`finally` 中仅终止自己启动的进程。
- 浏览器：`BROWSER_PATH` 或默认 `.tmp/browser/chrome-linux/chrome`；不存在时提示需要先准备浏览器，
  不自动下载。无头 SwiftShader 渲染，验收结论仅代表 headless 渲染，不代表物理投影设备性能。
- 输出目录：`MOTOR_LAB_OUTPUT`（默认 `.tmp/motor-lab-real-check/`），含截图与 `report.json`。
- 前端契约：`window.motorLab.getState()`（只读）与 `window.motorLab.getSceneStatus()`
  （`ready/errors/models[{id,loaded,meshCount,source}]/ports[{id,x,y,visible}]/cameraPosition/cameraTarget`）。
  测试用 `ports` 的 CSS 像素投影坐标做真实拖拽，不写死旧坐标或相机参数。

### 当前验证状态（真实模型接入阶段）

- 前端代理请求超时且未落代码后，由主模型实现真实模型加载/显示/交互和只读测试钩子。服务与测试代理已写初稿，主模型补回归并纠正原测试将链路ID误当端口ID的错误。
- 主模型实跑：26项真实模型浏览器检查通过，0错误/0跳过/0外部请求；81项Node单测通过；5项本地服务安全测试通过。证据：`.tmp/motor-lab-real-check/report.json`。旧`tests/motor_lab.browser.mjs`改为同一真实模型测试入口，原粗模相机常量不再有效；新测试改用真实投影并额外验证每条链路都能手动拖线、缺件禁用、代码注入拒绝/反转/故障/相机独立旋转平移缩放，未仅依赖自动接线。
- 首屏检查包括6个模型主体包围盒角点及14个功能端点在视锥内；resize/390px导航可达。软件SwiftShader验证不能替代实际投影设备性能。
- 已移除旧器件方块构造器，不降级回占位模型；缺任何源GLB时显示错误并禁止接线/运行/代码操作。运行六件为TB47D、兼容电池架、中心板2、C板、C620、M3508。

### 展示与接线边界

- 所有模型以米为源单位，整体统一20倍展示尺度，不逐件归一。电池与电池架分离相邻放置，不冒充就位装配。
- 彩色功能端点/线头为教学示意：部分中心板端点使用已辨认网格中心，其余以真实主体边界作候选，**不是已验证插座的配合面/针脚**。能够虚拟接线不表示可照此进行实物接线。
- C620、M3508已辨认长线网格仅在运行时隐藏，源文件不变；自建曲线和简化线头替代原长线外观。主控与中心板4-pin定义不混用，原物理线序未认证。
- M3508静态轴外形显示，不让整机自转冒充轴动画；轴独立分组及准确枢轴仍待机械几何复核。转速、角度为原教学SIM计算，不是硬件反馈。
- 新源文件仍在本地`.tmp/`及既有受限资产目录，清理会使专用实验台缺件。公开分发许可、稳定资产归档与目标设备性能尚待后续处理。

## 四、失败排查

- 端口被占用：默认 port 0 自动分配；`--port` 冲突时服务抛错退出，换端口即可。
- 浏览器缺失：准备 `.tmp/browser/chrome-linux/chrome` 或设置 `BROWSER_PATH`。
- 模型 404：核对上表磁盘来源文件是否存在；缺件场景在页面侧应表现为 `ready=false` 且不能运行。
