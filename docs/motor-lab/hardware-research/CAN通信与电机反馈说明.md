# Motor Lab CAN通信与电机反馈说明

本文件以 **M3508＋C620** 为对象。所有协议结论限定于[调查报告S06](硬件资料调查报告.md#s06)所列官方手册；不外推至GM6020、C610、达妙或任意UART设备。

## 1. 协议分层与设备ID

**已确认**：手册中文物理页31–33/35说明CAN控制，1Mbps，标准数据帧，DLC为8字节。CAN总线仲裁ID不是串口地址，也不是电机单独接收8字节就能理解的UART数据。

| 名称 | C620含义 | 官方定位 |
|---|---|---|
| 电调设备ID | 1–8，用于选定控制槽及反馈标识符；应在同一C620网络内避免重复ID | S06页30–32 |
| 控制帧ID 0x200 | 同时携带电调ID1、2、3、4的目标 | S06页31–32 |
| 控制帧ID 0x1FF | 同时携带电调ID5、6、7、8的目标 | S06页32 |
| 反馈帧ID | 0x200＋设备ID，即0x201–0x208 | S06页33 |

设备ID不是“把每个电机的电流直接发到0x201”。0x201在该协议中是ID1的反馈帧。SET键设置与快速分配方法可查手册，但本轮没有执行设置，也不提供实物操作步骤。

**多设备共网边界**：其他DJI型号也可能使用重叠CAN标识符；把C620、C610、GM6020等混在一网时须逐项查各模式与ID规划。只要软件枚举名称不同，不代表线上标识符不会冲突。本报告不交付混网方案。

## 2. 主控→C620控制帧

**已确认**（S06物理页32）：每个目标为有符号16位数，高8位在前。raw范围为 `-16384…+16384`，对应**目标转矩电流** `-20…+20 A`；这不是RPM、输出轴角度、PWM占空比、电池电流或安全实验限值。

| 字节 | 0x200控制对象 | 0x1FF控制对象 | 内容 |
|---|---|---|---|
| 0、1 | ID1 | ID5 | 目标raw高字节、低字节 |
| 2、3 | ID2 | ID6 | 同上 |
| 4、5 | ID3 | ID7 | 同上 |
| 6、7 | ID4 | ID8 | 同上 |

**算术推导**：此命令标度下，目标电流可表示为 `I_target = raw × 20/16384 A`。标度不等于设备或机构允许长期工作的电流，亦不能直接当作反馈电流换算公式。

### 离线编码例子（教学算例，不发送）

设四槽raw为 `[1000, -1000, 0, 0]`，group1：

```text
标准数据帧ID = 0x200，DLC = 8
DATA = 03 E8 FC 18 00 00 00 00
```

`1000=0x03E8`；`-1000`的16位补码为`0xFC18`。数值只用于说明编码，**不是推荐测试电流**。即使只教学一台电机，帧仍有四个槽；其他槽必须按总线控制策略合并，不能由不同任务轮流发送并相互清零。

## 3. C620→主控反馈帧

**已确认**（S06物理页33）：默认1kHz发送，频率可在RoboMaster Assistant中修改。表中“高8位/低8位”意味着先拼接完整字段，不能把每字节分别当成物理量。

| 字节 | 官方字段 | 单位/含义与边界 |
|---|---|---|
| 0、1 | 转子机械角度高/低8位 | 0–8191，转子单圈角度；不是减速输出轴完整角度，也不是电角度 |
| 2、3 | 转子转速高/低8位 | RPM；需按带符号值解读方向，不是车轮速度 |
| 4、5 | 实际转矩电流高/低8位 | 保留原始字段；该反馈表未明确给出安培换算及完整量程，不能直接照抄命令比例或声称为N·m/电池总电流 |
| 6 | 电机温度 | ℃；不要擅自改称电调MOS温度，也不推断传感器具体位置/型号 |
| 7 | Null | 不赋予业务语义；手册未在该表承诺每次必须为0，不将非0自动视为故障 |

### 转子与输出轴不能混用

- **算术推导**：转子角度 `theta = encoder × 2π/8192`；转子角速度 `omega = rpm × 2π/60`。这是单位换算，不是新协议。
- **已确认**：M3508 P19手册[S07](硬件资料调查报告.md#s07)物理页13列减速比 `3591/187`（约19.2:1）；简介页8粗略写约19:1。
- **教学抽象**：理想固定传动比下，输出轴转速可由转子转速除以减速比估算；它不是包含负载/效率/打滑的动力学模型。
- **待核实/待设计**：要得到输出轴连续位置，需解包转子多圈、初始机械参考、方向约定、采样与丢帧边界。单个0–8191角度除以减速比不能恢复完整输出轴位置。现有代码没有完成这些步骤。

### 离线反馈解码例子（人为构造，不是采集记录）

```text
ID = 0x201，DLC = 8
DATA = 10 00 FF C4 00 64 19 00
```

- `0x1000=4096`：转子角度π rad；
- `0xFFC4=-60 RPM`：转子角速度−2π rad/s；
- `effort_raw=100`：保留raw，**不标100A或某个精确N·m**；
- 温度`0x19=25℃`；末字节示例填0，不表示协议强制其为0。

## 4. 现有仓库代码与真实协议的关系

依据[调查报告S10](硬件资料调查报告.md#s10)链接的实际文件：

| 函数/结构 | 当前已存在行为 | 没有做的事 |
|---|---|---|
| `dji_protocol(c620_current)` | `limit=16384, first_tx=0x200, second_tx=0x1FF, rx_base=0x200, count=8` | 不检测真实电调设置/固件 |
| `encode_dji` | 检查group和raw范围，高字节优先，返回8字节CAN帧 | 不访问CAN设备，不发送，不做机构安全限流 |
| `decode_dji` | 检查帧有效性/DLC/ID/角度范围，转换转子角度与速度，保留`effort_raw`和温度 | 不把反馈raw换为A/N·m，不解包多圈，不折算输出轴，不执行PID |
| `dji_current_amp_full_scale` | 电流模式下返回协议满量程知识，C620为20A | 不能由这个辅助函数推导当前实际电流测量标定 |

这是网页静态参考片段，不是已经接入C板的完整项目；缺少的传输层、CAN初始化/过滤器、发送调用、接收注册、控制任务及保护链路仍待核实。本轮没有编译、刷写或运行该固件。

## 5. CAN终端与控制方式选择

- **已确认**：C620手册页24说明ON/OFF接入/断开120Ω；[TI S08](硬件资料调查报告.md#s08)物理页5说明高速CAN主干两端终端原则。主控和中心板的实际终端状态未核实，不能假定“缺一个就随便补”。
- **已确认**：C620支持CAN与PWM两种控制输入，但手册禁止同时接入两种信号端口，切换须断电；不是“PWM与CAN可随时并用”。[S06页21/24]
- C620的PWM/RX与TX端也用于适配调参工具；该事实不表示可以用任意自拟UART命令替代运行CAN协议。[S06页24–25]

## 6. 未来教学模拟协议：必须另命名，不冒充DJI

**教学抽象/尚未实施**：若未来通过浏览器、UART或日志交换目标值，可设计带版本号的`Motor Lab SIM`消息，例如显示设备号、目标raw、转子角度、时间戳和来源`simulated`。这里不规定最终串行格式、波特率或校验。

边界要求：
1. 只有按S06构造的CAN ID/帧格式/字节域才称“C620真实协议”；用JSON、CSV或文本发送的教学消息不是DJI CAN帧。
2. UART波特率、序列化、CRC、发布订阅Topic都属未来项目设计，未经实际固件证据不能称现有架构。
3. 若动画把电流目标直接映射成转速或用理想惯性参数，必须标“简化仿真”，不能称M3508经标定的动力学模型。
4. 不把模拟反馈画成真实硬件采样；没有CAN硬件访问或串口连接时，界面应明确离线。

本报告只提供协议依据与设计边界，不增加发送按钮、不实现协议桥接、不连接硬件。
