# RM 电控教学系统｜GLB 装配修复工作台实施方案（MR-1）

**基线**：`3Fish3/-1014`，`feat/ui-v2-p1`，检查时 HEAD `2d079f5d90712454d3b043ce5190499d169914ec`  
**建议工作分支**：`feat/model-assembly-editor`（从 `feat/ui-v2-p1` 建立）  
**目标**：在完全离线的 Web 工作台中定位、选中、移动、旋转一个离群电机组件；保存可追溯的修复补丁，并导出经验证的独立 GLB，供第二章第 10 步对照展示使用。

> 教学系统当前目标是视觉正确、结构可解释；**任何软件修复都不自动等于恢复了 SolidWorks 的真实装配约束**。未经实物或原 CAD 核实的安装位置应标记为“人工调整，待机械核验”。

## 0. 当前仓库事实与核心问题

- `web/models/hero_robot_clean.glb`：6,150,804 字节，574 个节点、183 个 mesh、约 213,790 三角面；`docs/model-stats.json` 提供源/简化模型统计。
- `web/js/viewer.js` 的 `loadHeroRobot()`（约 237–286 行）使用 `Box3().setFromObject(model)` 的全体包围盒求缩放及中心。偏离主体的电机会把包围盒撑大，导致第 10 步机器人显示非常小。该逻辑属于**教学展示变换**，不应成为装配修复的坐标依据。
- `web/js/app.js` 的第 10 步仍硬编码 `./models/hero_robot_clean.glb`（约 284 行）；上线修复版需要可验证、可回退的资源选择。
- 目前仓库内置 Three.js r180、`GLTFLoader.js`、`OrbitControls.js`，未见 `TransformControls.js` 与 `GLTFExporter.js`。不要加载外部 CDN。
- `scripts/optimize_models.py` 以 `gltfpack -kn -km -si 0.08 -noq` 产出轻量化模型。模型重建后节点或拓扑可能变化，**补丁不能无校验地跨模型版本复用**。
- P1 已统一十步白色投影风格。独立工具也必须使用白/浅灰/蓝配色，不能回到 V1 深色 HUD。
- 最新 P1 GitHub Actions 已完成三套浏览器测试但最终 `git diff --exit-code` 失败，原因是 P1 测试向受版本管理的 `docs/ui-v2/p1/` 写出环境相关的截图/报告。应把 CI 临时输出统一重定向至 `.tmp/ci/`，不要覆盖交付证据。

## 1. MVP 功能边界（必须完成）

### 1.1 模型读入与定位

1. 页面 `web/model-editor.html` 可用文件选择器加载用户本机 `.glb`，也可点击“加载课程整车模型”打开仓库预置模型。所有解析在浏览器本地完成。
2. 使用**未经过课堂归一化**的 `GLTFLoader` 原始 `gltf.scene` 作为编辑场景，保留层级、材质和原有局部变换；编辑器自己计算观察相机，不复用 `loadHeroRobot()` 中的缩放容器。
3. 左栏可搜索、展开 GLB 节点树，显示节点名、层级路径、GLB `nodeIndex`、父节点、是否含 mesh、局部/世界位置，以及几何包围盒。
4. “异常候选”只做统计提示，例如组件中心距离主体中位中心较远或导致总包围盒急剧扩张；不自动修改、不默认认定该候选一定是电机。
5. 节点选择后高亮、框选聚焦、可隔离显示/隐藏；**隐藏状态不作为导出的装配修复**。

### 1.2 操作与安全

1. 使用与 r180 匹配的 `TransformControls`，支持**移动、旋转**；允许切换局部/世界操作轴。
2. 提供可编辑的 XYZ 位置、欧拉角输入框（界面单位为度；内部四元数），可微调步进。P0 不需要复杂缩放编辑，避免破坏几何比例。
3. 选中的是**一个真实 glTF 节点或装配组**而非临时高亮 mesh。父子链的世界矩阵变化和局部变换转换必须正确。
4. 支持撤销/重做（至少 20 级）、单节点复位、恢复全部初始变换；未保存时导航离开给予提示。
5. 一次编辑仅修改已明确选中的节点；其他节点、几何、材质、索引及贴图不应改变。
6. 不允许无确认直接“自动放回电机”；建议对称位置信息只能作为**预览建议**，需讲师确认。

### 1.3 两种保存（同一份修复事实）

- **配置 JSON**：保存目标文件 SHA-256、文件体积、GLB 节点索引/路径、原始局部变换、修复后的局部变换、变更说明、是否已实物核验。重新打开时先校验哈希与节点兼容性，不一致则拒绝自动套用并显示差异。
- **独立修复 GLB**：命名为 `hero_robot_repaired.glb`，通过下载到用户本地保存。浏览器纯静态服务**不能直接覆盖仓库文件**。本地 Agent 后续经人工确认可复制到 `web/models/` 供课堂使用。

**首选 GLB 导出技术**：基于 GLB 2.0 二进制块结构，对原始 JSON chunk 中目标 glTF 节点的 `translation`/`rotation`/`scale` 或 `matrix` 做最小更新，重建正确 4 字节对齐的 JSON chunk 与文件总长，**原样保留 BIN/其他合法 chunk 字节**。这样对“只修变换”的场景比整场景 `GLTFExporter` 重新编码更可控，且能保留原始材质、未知扩展与二进制几何。解析及导出必须提供充分测试、拒绝无效/不支持的 GLB。

`GLTFExporter` 可作为后续**明确标记为重导出模式**的备选，但不应在第一版默默对 574 节点及其材质/拓扑做重编码。

补丁草案（字段名可调整，语义必须保留）：

```json
{
  "schemaVersion": 1,
  "source": {
    "filename": "hero_robot_clean.glb",
    "sha256": "<源文件实际 sha256>",
    "sizeBytes": 6150804
  },
  "coordinateSpace": "local",
  "edits": [
    {
      "nodeIndex": 123,
      "nodePath": "Scene/.../MotorAssembly",
      "original": {"translation": [0, 0, 0], "rotation": [0, 0, 0, 1], "scale": [1, 1, 1]},
      "repaired": {"translation": [0, 0, 0], "rotation": [0, 0, 0, 1], "scale": [1, 1, 1]},
      "note": "人工修正位置，待机械核验",
      "verifiedAgainstCAD": false
    }
  ]
}
```

以上 `123` 和坐标**仅为格式占位符**，不是对用户电机位置的推断。

### 1.4 节点映射关键点

- 必须将 Three.js 选中对象明确关联到**原始 GLB glTF `nodes[]` 数组索引**，优先利用 `GLTFLoader` parser 的节点依赖/关联映射并进行挂载检查；同名节点不能仅靠名称识别。
- 记录原始 glTF 变换表达形式（`matrix` 与 TRS 不能同时写入同一节点）；对原本有 `matrix` 的节点按相同表示更新矩阵，其他节点更新 TRS。四元数归一化、检查数值有限、矩阵可分解性及父变换。
- 选中父装配组时显式告知将同时移动其子组件；避免只移动电机外壳、不移动对应轴承、安装座与子零件。
- 若被选节点无法稳定关联 glTF nodeIndex，禁止导出，提示“无法识别源节点映射”。

## 2. 页面设计：`model-editor.html`

- **顶部**：返回课程｜模型名及哈希缩写｜保存 JSON｜导出 GLB｜载入课程模型。
- **左栏（约 22%）**：层级树、搜索、异常候选、可见性和选中高亮。
- **中间（约 55%）**：白色三维工作区，网格、坐标轴、TransformControls，焦点/整车镜头按钮。提供“计算主体范围时暂时排除离群件”模式，但不删除它。
- **右栏（约 23%）**：当前节点信息、位置 XYZ、旋转 XYZ、局部/世界模式、微调/撤销/复位、模型来源说明和“未核实”提示。
- **底部状态**：节点数、已编辑节点数、是否未保存、导出前检测状态。不要叠加课堂第 9 步的运动滑块与演示控制。
- **快捷键**：W 移动、E 旋转、F 聚焦、Ctrl+Z 撤销、Ctrl+Shift+Z 重做、Esc 取消选中；输入框聚焦时不能抢快捷键。

```text

    repair-patch.js                 # JSON schema、SHA-256、哈希校验

  vendor/three/TransformControls.js # 与 Three.js r180 版本一致，离线可用
```

## 4. 开发分阶段与交付门

### MR-1：可操作编辑器（首个交付）

- 建立 `feat/model-assembly-editor`；与 P1 教学页解耦。
- 加载课程现有优化 GLB；节点树、关键部件筛选、高亮和选中聚焦。
- 变换手柄移动/旋转、局部/世界轴、数值输入、撤销/重做、复位。
- 导出 JSON 修复补丁、重新导入并校验源文件哈希；**不自动提交修复好的电机位置**。
- 产物：工作台截图、疑似异常节点清单（名称、层级、位置、包围盒）、交互录像与 Playwright 测试。

### MR-2：安全导出与校验

- 实现 GLB chunk 级节点变换修改；下载修复版 GLB。
- 导出后重新导入验证 glTF 合法性、节点数/层级、非目标节点 TRS、BIN chunk SHA-256/字节一致、mesh 和材质信息稳定。
- 测试无效文件、重复节点名、嵌套父子变换、matrix/TRS 节点、四元数归一化、出界数据、哈希不匹配。
- 一旦编辑状态未“人工确认”，仍允许下载草稿 GLB，但清楚标记“未核实草稿”；**课堂默认资源不可自动切换**。

### MR-3：课堂集成与视觉验收

- 手工审核电机修复位置，保存 JSON 补丁及最终 GLB；明确“机械位置已核验”或“仅视觉修复”。
- 修改第 10 步 GLB 路径选择（推荐课程配置清单显式引用修复版，失败回退原版并提示）；先独立装载验证再接入教学。
- 基于修复后几何，按**两个模型主体分别**计算观察范围，改善第 10 步占比。目标：主要模型投影清晰、无裁切；不拿异常件撑大包围盒，不默默隐藏真实结构。
- 双分辨率 1920×1080 / 1366×768 真实截图，演示与老师工具未回归；修复真实来源说明，未核实的硬件型号不写死。

## 5. 验收标准（阻断交付的硬条件）

1. 原始 `hero_robot_clean.glb` SHA-256 前后完全相同；不覆盖用户原始 CAD/STEP/GLB。
2. 能选中任意一个真实 glTF 节点，独立移动、旋转、复位、撤销/重做；另一个未编辑节点的**局部变换**在导出后不变。
3. JSON 补丁绑定源 SHA-256；不同源文件或节点映射不匹配不能静默应用。
4. 导出 GLB 能被当前 Three.js GLTFLoader 重新打开，且 `gltf-validator` 不新增错误；节点数、非目标变换与二进制几何保持；必要时比对修复前后世界空间包围盒。
5. 修复前后真实截图能看到同一电机从离群位置回到人工确定的位置；记录确认依据；没有依据就不得声称精准装配恢复。
6. 课件 10 步布局和差速行为不回归；第 10 步镜头与模型占比通过人工投影审查。
7. 全离线、本地服务器可运行；无外网 CDN、无上传用户模型的行为。
8. CI 执行不会修改受版本控制的 `docs/ui-v2/p1` 证据；修复脚本和测试输出一律指向 `.tmp/ci/`。合并前 GitHub Actions 为绿色。
9. 单独记录软件渲染和课堂真实设备的 FPS/内存，不用无头软件渲染替代实际设备结论。

## 6. 请本地 Agent 遵守的边界

- 先发现异常节点，**不要**通过距离阈值自动剪切、删除、缩放、归位。
- 不更改 `web/js/kinematics.js`；不重写教学系统的 10 步数据和运动学。
- 不修改未核验的硬件型号、机械装配归属、供电接线等教学事实。
- 不把本地编辑器的辅助网格/轴/高亮/镜头偏移写进 GLB。
- 不一边导出 GLB 一边把归一化展示 wrapper 一起序列化，避免产生错误尺寸与原点。
- 不直接从独立编辑器写服务器文件；下载交付物后，**经审核**再由 Agent 将它加入仓库。
- 每阶段提交独立 commit，完成后提供真实截图、修改文件清单、测试记录和仍无法确定的机械装配问题。

## 7. 完成后交接信息

最终交付应包括：`model-editor.html`、变换编辑源码、`TransformControls` 离线依赖、JSON/GLB 导出机制、修复样例和源哈希、单元/浏览器测试、模型重新加载验证、人工确认记录、与原 P1 对照截图及风险清单。

**第一步不需要猜出飞离电机的安装位置**。先交付一个能看见节点层级、精确选中、移动旋转、保存重开、导出校验的工具，然后通过实际机器人照片或 CAD 信息确定位置，再集成到课堂。
