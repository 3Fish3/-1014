## 当前接入范围

仓库：`3Fish3/-1014`。现有 GitHub MCP 已连接，已成功读取 `feat/ui-v2-p0` 的 `package.json`。未改变全局MCP配置，未新增凭据或仓库Secrets。

仓库当前公开，读取成功并不证明认证身份或写权限；创建Issue/PR等写操作尚未测试。SSH推送授权和MCP的GitHub API授权是两套机制。

在Pi里可用 `/mcp` 查看连接、工具和认证状态。当前GitHub MCP暴露26个仓库/Issue/PR工具，不含Actions运行查询工具。不要将令牌发送到对话、写入项目或提交Git。需要扩大授权时，优先仅授权该仓库及必要功能。

## 自动执行什么

`.github/workflows/verify-and-package.yml` 在包含该工作流的分支发生push、PR时运行，并声明手动触发入口。

1. 安装锁文件规定的Node依赖及匹配的Playwright浏览器、中文字体。
2. 运行运动学与CI规则测试。
3. 校验已经提交的两个GLB模型。
4. 启动回环静态服务器，执行V1全课程与V2 P0双分辨率浏览器检查。
5. 验证通过才对当前提交执行`git archive`并生成SHA256校验文件。
6. 上传下载产物。本次验收的报告/截图另存，不覆盖仓库既有交付证据。

工作流固定官方Actions的已核验完整提交SHA，仓库权限为`contents: read`，checkout不保留凭据。不配置Secrets、自动合并、Pages、Release、部署、AI后台自修改代码或强制推送。PR使用普通`pull_request`，不是高权限`pull_request_target`。

GitHub runner使用其自身网络，不能访问开发电脑的7897/7898代理。不执行依赖本机Downloads原模型的重建脚本，也不在每次CI里重新生成PDF、视频。

## 去哪里看和下载

[仓库Actions页面](https://github.com/3Fish3/-1014/actions) → **Verify and package** → 对应提交的运行。

- `verified-source-<提交SHA>`：包含源码ZIP和SHA256。ZIP来自已提交文件，含网页、模型、讲义、PDF、视频与手册；不含Git历史、node_modules、虚拟环境和临时文件。报告里已有的素材与本次CI截图不是同一回事。
- `validation-evidence-<运行ID>-<尝试次数>`：本次模型报告、V1/V2截图、浏览器报告和本地服务日志。测试失败时也尽量上传已有诊断；失败证据不是通过证明。
- 保留7天，到期需重新运行。下载GitHub Actions产物通常需要登录。
- 发生失败时先看红色步骤和该次证据，不用旧截图或本地通过替代云端通过。

**分支边界**：本次工作流先推送至`feat/ui-v2-p0`，不自动合并或覆盖`main`。GitHub的手动“Run workflow”入口通常要求该工作流存在于默认分支；在用户决定合并前，当前功能分支的push仍能自动触发，但不要承诺默认分支已有手动入口。

## 本地复现

先运行`npm ci`、安装匹配的Playwright Chromium（或设置`BROWSER_PATH`），再启动`bash scripts/run_server.sh 8080`。另一个终端执行：

```bash
npm test
OUTPUT_DIR=.tmp/ci/models node scripts/validate_models.mjs
OUTPUT_DIR=.tmp/ci/v1 node scripts/browser_check.mjs http://127.0.0.1:8080
OUTPUT_DIR=.tmp/ci/v2-p0 node scripts/ui_v2_check.mjs http://127.0.0.1:8080
```

不指定`OUTPUT_DIR`时，三个脚本仍沿用原有输出位置；需要保护已交付证据时一定指定临时目录。浏览器测试失败会非零退出，并保存失败报告、尽可能保存当时截图。

浏览器使用本地受信任网页与无头软件渲染，测试性能不代表课堂设备GPU表现。CI不替代投影设备试讲和峰值总内存测量。

## 后续如何协作

可要求助手读取Issue、查看PR、根据失败报告修复并提交；写入仓库、合并、发布等按当次明确授权执行。当前配置只做到自动验证和打包，不表示会话结束后AI仍在后台持续改代码。
