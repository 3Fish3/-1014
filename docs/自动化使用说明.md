## 当前接入范围

仓库：`3Fish3/-1014`。现有 GitHub MCP 已连接，已成功读取 `feat/ui-v2-p0` 的 `package.json`。未改变全局MCP配置，未新增凭据或仓库Secrets。

仓库当前公开，读取成功并不证明认证身份或写权限；创建Issue/PR等写操作尚未测试。SSH推送授权和MCP的GitHub API授权是两套机制。

在Pi里可用 `/mcp` 查看连接、工具和认证状态。当前GitHub MCP暴露26个仓库/Issue/PR工具，不含Actions运行查询工具。不要将令牌发送到对话、写入项目或提交Git。需要扩大授权时，优先仅授权该仓库及必要功能。

## 自动执行什么

`.github/workflows/verify-and-package.yml` 在包含该工作流的分支发生 push、PR 或手动触发时运行：

1. 安装锁文件规定的 Node 依赖及匹配的 Playwright 浏览器、中文字体（Noto Sans CJK）。
2. 运行运动学与 CI 规则测试（`npm test` 67 项全通）。
3. 校验 4 份已提交的核心 GLB 模型（`step_aligned`, `clean`, `inferred`, `diff_car`）及装配补丁，执行自由穿插检测。
4. 启动回环静态服务器，依次执行 10 项双分辨率无头浏览器端到端验收（V1 回归、V2 P0、V2 P1 十步、装配工作台、旧推定候选、Step 10 双视区、装配近景证据、独立结构查看器、STEP 对齐及第一章六场景导览 `hero_tour_check.mjs`）。
5. 检查本地工作区纯净（`git diff --exit-code`）。
6. 验证全绿通过才对当前提交执行 `git archive` 并生成 SHA-256 校验文件。
7. 上传下载产物与测试证据包（源码 ZIP 及本次 CI 的截图、报告和日志，保留 7 天）。

工作流固定官方 Actions 的已核验完整提交 SHA，仓库权限为 `contents: read`，checkout 不保留凭据。不配置 Secrets、自动合并、Pages、Release、部署、AI 后台自修改代码或强制推送。PR 使用普通 `pull_request`，不是高权限 `pull_request_target`。

GitHub runner 使用其自身网络，不能访问开发电脑的 7897/7898 代理。不执行依赖本机 Downloads 原模型的重建脚本，也不在每次 CI 里重新生成 PDF、视频。

## 去哪里看和下载

[仓库Actions页面](https://github.com/3Fish3/-1014/actions) → **Verify and package** → 对应提交的运行。

- `verified-source-<提交SHA>`：包含源码 ZIP 和 SHA256。ZIP 来自已提交文件，含网页、模型、讲义、PDF、视频与手册；不含 Git 历史、node_modules、虚拟环境和临时文件。报告里已有的素材与本次 CI 截图不是同一回事。
- `validation-evidence-<运行ID>-<尝试次数>`：本次模型报告、各场景步骤截图、浏览器报告和本地服务日志。测试失败时也尽量上传已有诊断；失败证据不是通过证明。
- 保留 7 天，到期需重新运行。下载 GitHub Actions 产物通常需要登录。
- 发生失败时先看红色步骤和该次证据，不用旧截图或本地通过替代云端通过。

**分支演进与边界**：该工作流自 `feat/ui-v2-p0` 引入，历经 `feat/model-assembly-editor`、`feat/hero-assembly-finalize`，当前在 `feat/ch01-hero-tour` 分支稳定运行并保持全绿。未获授权前不自动合并到 `main`。

## 本地复现

先运行 `npm ci`、安装匹配的 Playwright Chromium（或设置 `BROWSER_PATH`），再启动 `bash scripts/run_server.sh 8080`。另一个终端执行：

```bash
npm test
OUTPUT_DIR=.tmp/ci/models node scripts/validate_models.mjs
OUTPUT_DIR=.tmp/ci/hero-assembly node scripts/hero_assembly_audit.mjs
OUTPUT_DIR=.tmp/ci/v1 node scripts/browser_check.mjs http://127.0.0.1:8080
OUTPUT_DIR=.tmp/ci/v2-p0 node scripts/ui_v2_check.mjs http://127.0.0.1:8080
OUTPUT_DIR=.tmp/ci/v2-p1 node scripts/ui_v2_p1_check.mjs http://127.0.0.1:8080
OUTPUT_DIR=.tmp/ci/model-editor node scripts/model_repair_check.mjs http://127.0.0.1:8080
OUTPUT_DIR=.tmp/ci/inferred-assembly node scripts/inferred_assembly_check.mjs http://127.0.0.1:8080
OUTPUT_DIR=.tmp/ci/hero-comparison node scripts/hero_comparison_check.mjs http://127.0.0.1:8080
OUTPUT_DIR=.tmp/ci/hero-assembly node scripts/hero_assembly_evidence.mjs http://127.0.0.1:8080
OUTPUT_DIR=.tmp/ci/robot-viewer node scripts/robot_viewer_check.mjs http://127.0.0.1:8080
OUTPUT_DIR=.tmp/ci/step-alignment node scripts/step_alignment_check.mjs http://127.0.0.1:8080
OUTPUT_DIR=.tmp/ci/hero-tour node scripts/hero_tour_check.mjs http://127.0.0.1:8080
```

不指定 `OUTPUT_DIR` 时，部分脚本会沿用原有默认输出位置；需要保护已交付证据时务必显式指定临时目录。浏览器测试失败会非零退出，并尽可能保存现场截图与报告。

浏览器使用本地受信任网页与无头软件渲染，测试性能不代表课堂设备 GPU 表现。CI 不替代投影设备试讲和峰值总内存测量。

## 后续如何协作

可要求助手读取Issue、查看PR、根据失败报告修复并提交；写入仓库、合并、发布等按当次明确授权执行。当前配置只做到自动验证和打包，不表示会话结束后AI仍在后台持续改代码。
