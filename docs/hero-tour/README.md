# 第一章：英雄机器人结构导览

## 启动与讲师操作

在本次开发工作树根目录执行：

```bash
bash scripts/run_server.sh 8080
```

以终端实际端口为准，打开 `/hero-tour.html`。本地HTTP服务不能省略，不用 `file://`。授课资源与Three.js均在仓库中，无需联网下载；开发测试需要现有锁定Node依赖和Chromium，不连接任何硬件。

1. 开场完整展示，按旋转按钮暂停慢转。不会自动换课。
2. 下一步认识整车，逐个揭示三个功能名称，点名称突出对应区域。
3. 云台页点选Yaw、Pitch与同步带位置。箭头只解释方向，不驱动真实关节。
4. 底盘页查看车架、四轮组、电机；可隔离所选细节。最后点驱动电机停留，再由讲师推进。
5. 发射页手动查看通道所在装配、拨弹及摩擦轮动力部件。待确认项不会补猜。
6. 恢复整车回顾三个功能，再突出CAD中识别出的电机。后续入口使用已有第二章电机内容，不新增第三章。

底栏可上一步、下一步、恢复整车和重播当前场景；鼠标拖动或滚轮允许手动观察并取消镜头过渡。恢复整车结束隔离，重播重新进入当前场景的初始状态。

## 文件职责

- `web/hero-tour.html`：独立课堂入口。
- `web/js/hero-tour-config.js`：六场景、真实模块/细节索引、相机方向与文案。
- `web/js/hero-tour.js`：讲师控制与展示状态；复用原有 `SceneViewer`，不创建第二套渲染引擎。
- `web/css/hero-tour.css`：白色投影布局。
- [P0设计与节点映射](P0设计与节点映射.md)、[节点清单](节点清单.md)、[机器可读证据](node-map.json)。

配置只适用于冻结 `hero_robot_step_aligned.glb`。映射检查失败或资源加载失败应明确报错，不回退到原样/推定模型。导览高亮、显隐及箭头只在运行时存在，不导出改装后的模型。

## 测试命令

以下从工作树根目录执行；先启动本地服务。浏览器位置与输出目录可由环境变量覆盖。

```bash
npm test
OUTPUT_DIR=.tmp/ci/hero-tour \
  node scripts/hero_tour_check.mjs http://127.0.0.1:8080
```

`npm ci` 用于按锁文件准备开发依赖，可能需要联网；不把依赖下载说成授课的联网要求。Python解析器测试沿用项目 `.venv`。浏览器验收结果及双分辨率六场景截图见[验收报告](验收报告.md)；未实际运行的项目不得根据脚本存在就标为通过。

## 教学边界

CAD标注型号不代替实车铭牌。Pitch动力源、拨弹动力源、完整弹丸路径、电子板型待确认；同步带规格、工作面和张紧未认证。不讲Three.js原理、不做复杂机械计算、不增加动力学、碰撞或CAN控制。资源计数与软件渲染测试不能代替投影电脑上的帧率、内存和显存实测。
